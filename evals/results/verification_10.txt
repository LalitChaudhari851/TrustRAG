================================================================================
ABLATION 2: SINGLE-CALL INPUT RAIL FOR THE GUARD (TOKENS PER TURN)
================================================================================
1. Traditional NeMo Multi-Step Execution (Baseline):
   - Step 1: Self-Check Input Rail (prompt ~250 toks + completion ~30 toks)    = ~280 tokens
   - Step 2: Colang Dialog State & Intent Matching (~350 toks + ~40 toks)      = ~390 tokens
   - Step 3: Self-Check Output Rail (~400 toks + ~30 toks)                     = ~430 tokens
   - Total Multi-Step NeMo Guardrail Overhead:                                 ~1,100 - 1,200 tokens / turn

2. Consolidated Single-Call Input Rail (Ablation Design):
   - Consolidates Jailbreak + Prompt Injection + Off-Topic Domain Detection into a single structured prompt:
       * System Prompt (concise security rules + enterprise IT scope):         ~155 tokens
       * User Query (average turn length):                                     ~25 tokens
       * Structured JSON Completion (e.g. {"blocked": false, "intent": "tech"}): ~15 tokens
   - Total Single-Call Guard Overhead:                                         ~195 tokens / turn

3. Token Savings & Throughput Impact:
   - Token Reduction per Turn: ~1,100 -> ~195 tokens (-82.3% token consumption).
   - Under Groq Free-Tier Daily Quota (200,000 TPD):
       * Multi-Step NeMo exhausts 200k TPD quota in ~166 queries.
       * Single-Call Input Rail supports ~1,025 queries before daily quota exhaustion.
   - Latency Reduction: Drops guard evaluation from ~1.8s (3 sequential HTTP round-trips) to ~280ms (1 round-trip).
