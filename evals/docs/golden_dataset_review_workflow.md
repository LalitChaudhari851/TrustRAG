# TrustRAG Golden Dataset Review Workflow (v2)

## 1. Overview & Objective

This document defines the reproducible human review and verification procedure for transforming candidate synthetic seed records into the official **TrustRAG Retrieval Golden Benchmark v2**.

### Golden Benchmark Invariants:
1. **Zero Unverified Benchmark Claims**: A synthetic question generated by an LLM or script remains strictly labeled `unverified_synthetic` until an authorized human reviewer inspects the query, cited evidence, and expected answer.
2. **Explicit Audit Trail**: Every promotion or rejection produces an immutable `AnnotationEvent` recording the reviewer ID, UTC timestamp, explicit decision, and documented rationale.
3. **Evidence Conjunction Verification**: Multi-hop queries must have verified alternative sufficient evidence sets. Conjunction success requires that all chunks in at least one sufficient set are present.
4. **Answerability Isolation**: Unanswerable queries must be strictly separated into `corpus_unanswerable` and `unresolved_evidence` with an explicit documented rationale.
5. **Freeze Gate Integrity**: Exporting a benchmark freeze fails if any record is pending, rejected, or missing required audit fields.

## 2. CLI Command Reference

All review workflows are executed via `evals.annotation_cli`:

```bash
# 1. View review progress and dataset breakdown
python -m evals.annotation_cli stats

# 2. List pending records requiring review
python -m evals.annotation_cli list --status pending
python -m evals.annotation_cli list --status unverified_synthetic --split dev

# 3. Inspect a specific record
python -m evals.annotation_cli inspect seed_001

# 4. Verify candidate chunk evidence against local corpus
python -m evals.annotation_cli verify-evidence seed_001

# 5. Verify chunk UUID presence in Qdrant vector index
python -m evals.annotation_cli verify-qdrant seed_001
python -m evals.annotation_cli verify-qdrant

# 6. Approve a record with documented rationale
python -m evals.annotation_cli approve seed_001 \
  --reviewer "alice@trustrag.io" \
  --reason "Verified exact commands in chunk 3 of parallel_work_queue.txt." \
  --answerability answerable

# 7. Reject an ambiguous or unsupported candidate record
python -m evals.annotation_cli reject seed_018 \
  --reviewer "bob@trustrag.io" \
  --reason "Question is ambiguous and cited chunk does not state the exact parameter name."

# 8. Export verified-only benchmark freeze
python -m evals.annotation_cli export-verified --output evals/data/retrieval_golden_verified.json
```

## 3. Human Reviewer Procedure

### Step 1: Query & Expected Answer Verification
- Read the question text. Is it clear, unambiguous, and phrased like a real enterprise engineer's question?
- Read the expected answer. Is it factually correct and directly answers the question?
- For unanswerable queries: verify that the question cannot be answered from the approved true corpus and that the reason is documented.

### Step 2: Evidence Provenance & Content Inspection
Run:
```bash
python -m evals.annotation_cli verify-evidence <record_id>
```
Inspect the output:
1. **Source File**: Confirm that the candidate chunk originates from an approved document in `processed_data/true/`.
2. **Chunk Text**: Read the stored text. Does the chunk contain sufficient factual evidence to answer the query?
3. **Quote Alignment**: The CLI checks whether cited quotes are exact substrings or paraphrases. Paraphrased quotes should be flagged or corrected.
4. **Relevance Grade**: Assign a relevance grade from 0 to 3:
   - `3`: Primary direct answer.
   - `2`: Highly relevant context or partial answer.
   - `1`: Marginally relevant background.
   - `0`: Irrelevant or distractor.

### Step 3: Multi-Hop Conjunction Verification (If Applicable)
For `answerable_multi_hop` queries:
- Confirm that answering the question requires information from **multiple distinct chunks**.
- Verify that every sufficient evidence set contains at least 2 valid chunk UUIDs.
- Confirm whether alternative sufficient sets exist (e.g. if the same fact is stated in two different documents or sections).

### Step 4: Adjudication (Approve or Reject)
- **To Approve**: Run `python -m evals.annotation_cli approve <record_id> --reviewer "<id>" --reason "<rationale>" --answerability <subtype>`.
- **To Reject**: Run `python -m evals.annotation_cli reject <record_id> --reviewer "<id>" --reason "<rationale>"`.

## 4. Benchmark Freeze Gate Requirements

Before a golden dataset can be frozen for formal model benchmarking, `export-verified` evaluates the following invariants:
1. **Zero Pending Records**: Every record included in the export must have status `verified_human`.
2. **Zero Fabricated Records**: If 0 approved records exist, the export generates a blocked manifest (`BLOCKED_PENDING_HUMAN_REVIEW`) rather than fabricating data.
3. **Required Audit Fields**: Every record must contain:
   - `reviewer_decision.reviewer`
   - `reviewer_decision.reason`
   - `reviewer_decision.timestamp`
   - Non-empty `review_history` event list.
4. **Zero Split Leakage**: Verbatim query overlap between dev and test is strictly forbidden.
5. **Deterministic Content Hash**: A SHA-256 hash is computed over all canonical record fields, guaranteeing tamper-evident reproducibility.

## 5. Known Limitations & Audit Findings (Seed v1)

From the v2 audit ([`golden_dataset_audit_v2.md`](file:///c:/Users/lalit/Desktop/Data%20Science/Production_Grade_Rag/evals/results/golden_dataset_audit_v2.md)):
1. **Paraphrased Quotes**: 63 evidence quotes in the synthetic seed dataset are loose paraphrases rather than exact character substrings of the corpus text. Reviewers must inspect chunk text directly using `verify-evidence`.
2. **Split Document Sharing**: All 6 source documents are shared across the current dev and test splits, and 6 candidate chunk UUIDs are referenced in both splits. While verbatim queries do not overlap, a document-disjoint split is recommended for post-freeze iterations.
3. **Small Sample Size**: The seed dataset ($N=50$) is an initial seed for pipeline calibration. Metric confidence intervals reflect this sample size.
